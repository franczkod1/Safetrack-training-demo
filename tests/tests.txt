# Tests

## Test 1 - Documents is a normal app page and employee hierarchy is aligned [sanity]
Viewport: desktop
Covers: full-page Documents workspace, upload control, employee hierarchy depth, fixed PNr column alignment, v0.24 version
Description: Verifies the primary v0.24 navigation/UI changes without using OCR.

Steps:
1. Open Mitarbeitende, expand Produktion and Maschinen- und Anlagenführung, and verify Produktion is visibly darker than the Tätigkeit while employee rows are white/light; verify visible PNr-#### values share one vertical column regardless of status
2. Open Menü and choose Dokumente; verify Dokumente appears as the normal main content page rather than a modal/popup and contains Dokumente hochladen and Erwartete Rückläufe
3. Open Menü and verify SafeTrack v0.24 is shown; verify the page remains usable without horizontal overflow

Expected: Hierarchy depth is clear, PNr values are aligned, and Documents behaves as a normal SafeTrack page with v0.24 visible.

## Test 2 - Uncertain page requires original-versus-return comparison
Viewport: desktop
Covers: page-specific original snapshot, uploaded receipt storage, OCR review state, GET page review endpoint, side-by-side leader control, manual confirmation guardrail
Description: Verifies a leader gets a meaningful visual reference before manually approving an uncertain page.

Steps:
1. Open Dokumente and click QA Vergleich vorbereiten; wait until QA Ergebnis shows a Vergleich ST-DOC id, then open that document
2. Verify Prüfen & abschließen is disabled while the page still requires review; open Vergleich öffnen for the uncertain page
3. Verify Digitales Original and Hochgeladener Rücklauf are displayed side by side with QR/Dokument-ID/Seite/Unterweisungs-ID/Version/PNr/Unterschrift comparison indicators, then use Seite nach Vergleich bestätigen

Expected: Manual approval is not blind: the leader can compare the page-specific digital original against the actual uploaded scan before confirming it.

## Test 3 - Employee document opens only the employee signature page by default
Viewport: mobile
Covers: multi-page completion, employee PNr page filtering, signed-page URLs, employee profile document link, expand-to-all-pages control, mobile overflow prevention
Description: Verifies an employee does not initially see every page of a multi-page signed group document.

Steps:
1. Open Dokumente and click QA Mitarbeiteransicht vorbereiten; wait until QA Ergebnis shows the target employee name, PNr and ST-DOC
2. Navigate to Mitarbeitende, search for the displayed target PNr, open that employee, verify Dokumentierte Abschlüsse contains the QA ST-DOC, and click Dokument öffnen
3. Verify the signed-document viewer initially shows only the page containing that employee's PNr/signature and offers Alle Seiten anzeigen; click it and verify all 3 pages become available without horizontal overflow

Expected: The employee profile defaults to the relevant signature page, while the full signed document remains available on demand.

## Test 4 - Printed confirmation emphasizes machine-readable identity
Viewport: desktop
Covers: group confirmation print preview, larger QR/quiet area, right-side official metadata block, larger Seite x/y, four-column signature table
Description: Verifies the v0.24 print layout is optimized for both paper signing and later machine recognition.

Steps:
1. Open Unterweisungen, select one training for Gruppenunterweisung, assign at least two matching employees, and prepare the Schulungsbestätigung preview
2. Verify the print preview has the title on the left and a compact metadata block at the upper right containing Unterweisungs-ID, Durchgeführt am, Version and Teilnehmende
3. Verify the page QR has a visibly generous white margin and is larger than before, Seite 1/1 is prominent, and the participant table contains Mitarbeitende Person, PNr., Tätigkeit and Unterschrift without a Datum column

Expected: The confirmation remains printable while QR, page numbering and document metadata are easier for SafeTrack to recognize later.
