# Tests

## Test 1 - Print, acknowledge, and reopen the central document [sanity]
Viewport: desktop
Covers: POST /api/documents/prepare, POST /api/documents/:id/snapshot, POST /api/documents/:id/printed, GET /api/documents, GET /api/documents/:id, GET /api/documents/:id/snapshot-url, central ST-DOC allocation, four-column print layout, document status, saved print snapshot, bulk upload entry point
Description: Verifies one concise print workflow centrally stores the document and its exact printable snapshot, then reopens it from Documents.

Steps:
1. Open "Unterweisungen", select exactly one broadly applicable training (do not select a second training), choose "Mitarbeitende zuweisen", select exactly two matching employees, enter the instructor fields, and open the confirmation preview
2. Verify the participant table contains only "Mitarbeitende Person", "PNr.", "Tätigkeit", and "Unterschrift", choose "Drucken", then return from the print flow and choose "Druck bestätigt – Dokumente öffnen"
3. Open the newly created document, verify status "Gedruckt – Rückupload ausstehend", verify "Dokumente hochladen" is available in the Documents view, then choose "Gespeichertes Dokument öffnen" and confirm the saved snapshot opens/triggers successfully

Expected: The confirmation has no participant Datum column, the Unterschrift column is wide, a central ST-DOC identifier and print snapshot are stored without a visible save error, the document has status "Gedruckt – Rückupload ausstehend", the bulk upload control is available, and the exact saved print snapshot can be reopened.

## Test 2 - Signed return is matched, reviewed, completed, and visible on the employee
Viewport: desktop
Covers: POST /api/uploads/store, POST /api/uploads/:id/analyze, POST /api/uploads/:id/finalize, GET /api/documents/:id, POST /api/documents/:id/complete, GET /api/documents/:id/file-url, GET /api/employees/:pnr/completions, QR/OCR comparison, leader approval, completion assignment, employee profile document link
Description: Uses the QA-only helper to create a central test document quickly, then runs the real signed-return storage, OCR/QR, review, completion, retrieval, and employee-profile pipeline. The helper is absent in normal SafeTrack use and automatically retries one transient upload-store failure just like the production bulk upload flow.

Steps:
1. Open "Dokumente" and choose "QA Rücklauf simulieren" once; wait until a document appears with status "Prüfung durch Führungskraft erforderlich"
2. Open that document, note its participant name and PNr., inspect "Automatische Prüfung", choose "Prüfen & abschließen", and confirm the action
3. Verify the document becomes green "Abgeschlossen – Mitarbeitenden zugeordnet", choose "Unterschriebenes Dokument öffnen", then find the noted employee by PNr. and verify the employee profile shows this ST-DOC under "Dokumentierte Abschlüsse" with "Dokument öffnen"

Expected: One click is sufficient even if the initial central store call has a transient failure; the return passes through real central storage and QR/OCR matching, requires leader approval, becomes green only after approval, the signed file is retrievable, the training completion is synchronized to the participant, and the same signed ST-DOC is accessible from the employee profile.
